## 1. 背景（一段话，够用）

TIC 是一个关于"智能计算"的理论，核心猜想是：多智能体在带宽受限信道下协作时，**协作成败取决于任务相关的抽象熵率 h_θ，而不是物理状态空间的原始熵率 h**。之前的九条相关定理全部只在人工植入划分结构的玩具环境里验证过（划分是设计者直接写死的，不是算出来的）。本实验要做的是：**在一个划分不是人工植入、而是算法从目标推出的、状态数足够大的环境里，硬撞这条预测。**

---

## 2. 精确定义（照此实现，不要意译）

### 2.1 环境骨架
- 有限状态集 S，有限动作集 A，随机转移核 P(s'|s,a)。
- 一个目标标注函数 g: S → L（例如 L = {未完成, 已完成, 违规}）。
- **物理熵率 h**：原始状态马尔可夫链（在给定策略下）的熵率，单位比特/步。用标准的经验估计（滑窗上下文的条件熵，或链的稳态分布下的转移熵）计算。

### 2.2 典范抽象 ~θ*（不是设计者选的，是算出来的）
用**划分精化算法**计算，伪代码：

```
Π_0 = 按 g(s) 分块（目标标注相同的状态分一块）
重复：
    对 Π_n 的每一块 B，按签名 s ↦ (P_a(B'|s))_{a∈A, B'∈Π_n} 再切分
    得到 Π_{n+1}
直到 Π_{n+1} = Π_n（不动点）
```

不动点就是 ~θ*。这是标准的 bisimulation/MDP 最小化精化（Paige-Tarjan 风格），**不是新算法，必须完全按此实现，不能用启发式近似替代**，否则后面的抽象类就不是理论意义上的 ~θ*。

- **h_θ（内禀任务带宽）**：商链（以 ~θ* 的块为状态的马尔可夫链）的熵率，单位比特/步。定义上 h_θ ≤ h（因为商链是原链的粗化，粗化只会减少不确定性）。

### 2.3 信道与智能体
- 2–4 个智能体，每个每步只能通过一条 **C 比特/步** 的信道发送一条编码消息（关于世界状态的信息），供其他智能体接收。
- 两种编码器，都要实现，用于对照：
  - **state-aware 编码**：直接对原始状态 s 做定长/变长编码，塞进 C 比特（状态数超过 2^C 时必须有损，用任意合理的有损方案，比如最近邻量化）。
  - **class-aware 编码**：先把 s 映射到它的 ~θ* 块，再对块编号做编码。
- 联合任务完成率 = 多轮 episode 中，全部智能体协作达成 g 定义的目标的比例。

## 3. 环境具体参数

- 二维网格世界，**物理状态数 ≥ 10³**（网格尺寸 × 每格可能状态，比如位置×资源等级×障碍配置的组合，凑够 10³ 以上）。
- 目标区域 + 若干可移动物体；转移带随机性（不是确定性网格，否则熵率退化没意义）。
- **关键约束**：任务相关的类数（|~θ* 的块数|）必须远小于物理状态数，且这个类结构是跑第2.2节算法算出来的，**不能人工指定"哪些状态算一类"**。这是本实验与之前四个实验最大的区别，也是这个实验存在的理由。

---

## 4. 扫描网格

两个轴：
1. **信道容量 C**：从明显小于 h_θ 扫到明显大于 h_θ（至少7个取值，覆盖预期崩塌点两侧）。
2. **任务粒度**：改变目标区域的粗细（更粗的目标 → 更小的 h_θ，参考 Corollary 4.1：目标越粗，~θ* 越粗），至少3档。

对每个 (C, 粒度) 组合，另外跑一次**物理状态数放大10倍、但任务结构不变**的版本（比如网格加密），用于测试"对物理状态数是否敏感"。

每个格点独立随机种子跑 ≥30 次取均值和方差（这不是可选项，见第6节反坑清单第1条）。

---

## 5. 主预测与证伪条件（先写在这里，不要等结果出来再套）

**主预测**：成功率作为 C 的函数，在 C ≈ h_θ 附近出现崩塌（陡降）；在 C > h_θ 处成功率高，且**网格加密10倍（h 大幅上升，h_θ 不变）时崩塌点和高成功率区应几乎不变**。

**次预测**：
- (a) class-aware 编码在同样 C 下应显著优于 state-aware 编码，且优势随物理状态数增大而扩大。
- (b) 若加入缓慢的目标漂移（目标区域随时间缓慢移动，产生非零 h_A），崩塌点应从 C≈h_θ 右移到 C≈h_θ+h_A。这一条是可选的加分项，时间不够可以跳过，不影响主预测的判定。

**证伪条件（照实报告，不要软化）**：若成功率跟随 h 而非 h_θ（比如加密网格后崩塌点明显右移），或对物理状态数明显敏感，**这条带宽定律就是被证伪了**。这不是失败的实验，这是有信息量的实验，按第7节格式如实报告。

## 6. 反坑清单（必须逐条自查，之前两次实验都栽在这类问题上）

之前的实验里出现过两次"代码能跑、数字很漂亮、但结果是假的"的事故，且事后证明**很难从结果本身看出来**，必须靠代码审查排除：

1. **每个智能体的随机性必须独立。** 之前一次事故：两个智能体用了同一个划分/分组顺序（同一随机种子或确定性顺序），导致"协作成功率100%"，但其实是两个agent在犯同一个错误，不是真协作。**检查：每个 agent 的编码器内部随机决策（如果有）必须用独立的随机数流，不能共享种子或确定性遍历顺序。**
2. **划分精化算法不能退化。** 之前一次事故：用错了函数变体，导致算法在没有目标信号时直接收敛到平凡划分（全部状态一类），产生的结果看起来"验证"了理论，其实是函数bug。**检查：跑一次 sanity check——在一个你手算过 ~θ* 的小例子（比如 5–10 个状态，自己画转移图）上先跑算法，确认输出和手算一致，再跑正式环境。把这个小例子的验证过程写进交回的报告里。**
3. **成功率不能因为任务太简单而恒为100%，也不能因为太难而恒为0%。** 扫描网格必须包含"确实会失败"和"确实会成功"的区域，否则曲线没有信息量。如果发现全网格都是100%或0%，先调整任务难度（比如缩短 episode 长度、增加干扰物体），不要直接报告"符合/不符合预测"。
4. **h 和 h_θ 的估计必须用同一套熵率估计方法**，不能一个用理论公式一个用经验估计，否则"h_θ ≤ h"这类不等式可能因为估计误差而看起来不成立。
5. **加密10倍那组实验，任务结构（目标定义、达成条件）必须严格不变**，只有物理格子密度变。如果加密时顺带改了目标定义，"h_θ不变"这个前提就不成立了，结果没有意义。
6. **报告原始数据，不要只报告结论。** 每个 (C, 粒度) 格点的均值、方差、跑了多少个种子，全部要留，回来给我审计的时候需要看分布不是只看均值。
